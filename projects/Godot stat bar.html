Godot stat bar

An augmented version of Godot's built-in progress bar, able to show change in value smoothly.

So far used in Ministry of Spinning.

Implmentation

Godot has 2 built-in progress bar nodes already, namely ProgressBar and TextureProgressBar. I chose to extend TextureProgressBar because it can be turned into a radial bar and be supplied a texture to draw on top of it.

I first set up a test user interface that only consists of the extended TextureProgressBar and a button that randomises the value of said progress bar.

Since value affects its fill, and that I want its change to be shown smoothly, I decided that a separate variable is needed to store the "actual value" set. This variable will be private by convention, and any changes to it will be made via functions. This allows the said change to be shown by interpolating the current fill display value to the set value every frame.

What I have at this point is already usable for my future Godot projects, but I also wanted the option of having this effect below that also works if the value is increasing instead. I do not know what exactly is this effect called, but I will call it difference visualisation.

The first thing that came to my mind is to simply duplicate the progress bar to be used as the visualiser. The visualiser bar will be updated first, followed by the main bar after the visualiser bar is done updating for a set amount of time. 2 additional textures are required, one for when the value of the visualiser bar is more than that of the main bar, one for the other way around. In Godot, given the same Z index, the nodes further down the scene tree are drawn on top of those further up. This is why the visualiser bar is made child of the main bar, as it is now below the main bar in the scene tree. And since Z index of a child is relative to its parent by default, if the value of the visualiser bar is higher, its Z index is simply set to -1, making the main bar be drawn on top instead. The check on both values is done every frame when the visualiser bar is updating, allowing the appropriate textures to be applied immediately.

This is when I discovered a bug where a lot of the times the main bar is never updated. I identified them to be caused by the fact that the visualiser bar is never considered to be finished updating, even though I used is_equal_approx to compare value and "actual value". This is because the progress bar's smallest step possible is 0.001 while the epsilon value that is_equal_approx uses is 0.00001, and crucially it is unable to be changed. Therefore, I simply copied the code for is_equal_approx from engine code to a custom function and have the epsilon value to be the same as the smallest progress bar step.

With the difference visualisation done, I thought about reusing the visualiser bar to preview values. I added 3 more functions, one to set the previewed value, one to confirm it, and another to cancel the preview.

I also updated the test user interface with a check button that toggles whether pressing the randomise value button sets or previews values, and 2 buttons for confirming and canceling the previewed value.

I found out that the previous bug actually has not been completely fixed, as there are still some values that could trigger its cause. I thought about changing the epsilon value, but I decided to skip waiting for the visualiser bar to finish updating, which is simpler and does not really change the effect siginificantly anyway.

Known bug(s) or issue(s)

When developing Ministry of Spinning I discovered that when reloading the scene containing the stat bar, the stat bar retains its previous current value. I have not yet identified its cause.

Future addition(s)

Right now the change in value is done by interpolating the current value to target value every frame, resulting in a big change initially and quickly resulting in small changes. I would like to add an option such that the change may be done by adding or subtracting a fixed amount every frame for a more consistent change.
